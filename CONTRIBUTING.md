# Contributing to Simple Interest Calculator

All contributions, bug reports, bug fixes, documentation improvements, enhancements, and ideas are welcome.

Thank you for taking the time to help improve this project! Please read the [Code of Conduct](CODE_OF_CONDUCT.md) before you start.

## Ways to Contribute

- **Report a bug:** open an [issue](https://github.com/arc12at/simple-interest-calculator/issues) describing what happened, what you expected, the steps to reproduce it, and your browser/OS.
- **Suggest an idea or enhancement:** open an issue explaining the feature and why it would be useful.
- **Fix a bug or add a feature:** submit a pull request (see below).
- **Improve documentation:** fixes to the README, comments, or typos are always appreciated.

## Getting Started

1. **Fork** this repository.
2. **Clone** your fork:
   ```bash
   git clone https://github.com/<your-username>/simple-interest-calculator.git
   cd simple-interest-calculator
   ```
3. **Create a branch** for your change:
   ```bash
   git checkout -b feature/your-feature-name
   ```
4. Open `index.html` in your browser to run the app — no build step needed.

## Making Changes

- Keep the project dependency-free (plain HTML, CSS, and JavaScript).
- Follow the existing code style: 2-space indentation, clear names, and short comments where logic isn't obvious.
- Keep changes focused — one feature or fix per pull request.
- Test your change in at least one modern browser, in both light and dark mode, and on a narrow (mobile) screen.

## Commit Messages

Write short, descriptive messages in the imperative mood, for example:

```
Add compound interest option
Fix rounding of total amount
Update README setup steps
```

## Submitting a Pull Request

1. Push your branch to your fork:
   ```bash
   git push origin feature/your-feature-name
   ```
2. Open a pull request against the `main` branch of this repository.
3. Describe **what** you changed and **why**, and link any related issue (e.g. `Closes #3`).
4. Add screenshots if your change affects the UI.

Your pull request will be reviewed, and you may be asked for changes before it is merged.
